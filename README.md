# XizmatGo

Мобильный сервис поиска специалистов и заказа услуг в Узбекистане. Публичный сайт и отдельная административная панель используют собственный проект Supabase; проект независим от ADAMARKET.

## Текущие возможности

- Адаптивная главная страница и каталог из 8 категорий.
- Форма заявки клиента с сохранением в `service_requests`.
- Форма заявки специалиста с сохранением в `specialist_applications`.
- Отдельная административная панель `admin.html`.
- В админ-панели: список заявок, поиск по имени/телефону/описанию, фильтрация по статусу, просмотр контактов, изменение статусов и счётчики.
- Row Level Security (RLS) включён для таблиц публичной схемы.
- Публикация настроена через GitHub Actions и GitHub Pages.

## Локальный запуск

Из корня репозитория выполните:

```bash
python -m http.server 8080
```

Откройте `http://localhost:8080`. Для работы форм нужен доступ к Supabase.

## Доступ администратора

Регистрация из админ-панели отключена. Войти может только существующий пользователь Supabase, у которого в `public.profiles` назначена роль `admin` и `is_active = true`.

1. Создайте пользователя в Supabase Authentication (email/password).
2. Назначьте роль администратора только доверенному аккаунту, подставив его email вместо `YOUR_ADMIN_EMAIL`:

```sql
insert into public.profiles (id, full_name, role, is_active)
select id,
       coalesce(raw_user_meta_data ->> 'full_name', split_part(email, '@', 1)),
       'admin'::public.account_role,
       true
from auth.users
where lower(email) = lower('YOUR_ADMIN_EMAIL')
on conflict (id) do update
set role = 'admin'::public.account_role,
    is_active = true;
```

Перед запуском проверьте, что email принадлежит именно вашему аккаунту. Если запрос добавил/обновил 0 строк, сначала создайте пользователя в Supabase Authentication.

Не передавайте пароль и не вставляйте service-role/secret key в HTML или GitHub. Административные права проверяются на стороне базы через RLS, а не только скрытием интерфейса.

## Авторизация

Публичные заявки можно отправлять без входа. Вход пользователей через Google и подтверждение телефона намеренно отложены до отдельного этапа; в панели управления используется существующая email/password учётная запись Supabase.

## Безопасность и границы проекта

- В браузере используется только publishable key.
- Не добавляйте service-role или secret key в клиентский код.
- Не ослабляйте RLS ради обхода ошибок интерфейса.
- XizmatGo использует собственный Supabase project `laqnpivpztmckykpnvyh`; базу ADAMARKET не использовать и не изменять.
- До публичного запуска необходимо выполнить сквозные тесты заявок, прав администратора и статусов на опубликованном сайте.
